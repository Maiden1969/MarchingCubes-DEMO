## Project

Unity 6 (6000.5.10f1, URP 17.5.0) demo of DRG-style fully destructible voxel terrain: SDF lattice per chunk, meshed with Marching Cubes via compute shader, edited at runtime (carve/add spheres). Editor is at `E:\Unity\6000.5.10f1\Editor\Unity.exe`. Language of user communication: Chinese.

  -projectPath "F:\UnityProject\DEMO" -logFile "F:\UnityProject\DEMO\compile_check.log"

## Pipeline status (read this first)

The compute-shader pipeline is wired end-to-end. The abandoned Burst-job refactor was deleted (2026-09-01): `Scripts/Terrain/*`, `Scripts/Grid/*`, `CubicMethod/Common.cs` + `ComputeShaderManager.cs`, `Shaders/Noise.compute` + `Math.compute`, `Scripts/Prefabs/Chunk.prefab` are gone.

**Scene is wired (verified 2026-09-03)**: `SampleScene.unity` has `ChunkManager` (chunkSize 32 / maxDistance 200 / updateFrequency 2 / sdfResolution 33; computeShader = MarchingCubes.compute, material = Default.mat, generationLayer = 6) and an `SdfWorld` GameObject whose children are `SdfFloor`/`SdfCapsule`/`SdfSphere` prefab instances. No missing scripts. `Nav.NavManager` must be added manually (empty GameObject + component; terrainMask defaults to layer 6). Interaction lives on `FlyCamera` (2026-09-11): left-click carves (radius serialized there, default 1.5), right-click raycasts and calls `CustomNavAgent.SetDestination(hit.point)` — the agent (e.g. a sphere GameObject with `CustomNavAgent`) is auto-found via `FindFirstObjectByType` if the serialized field is left empty. ChunkManager keeps only `CarveAt(hit, radius)` + `GenerationLayer`/`MaxDistance` getters for the camera to use.

**Sparse brick map (2026-09-11)**: `SdfField` no longer keeps a dense 33³ float lattice — persistent storage is a sparse brick map (`DS/BrickGrid`): 8³-voxel bricks (9³=729 corner values each, 4³=64 slots per chunk) + a dense 64-slot indirection table where absent bricks encode deep-solid/deep-air defaults (`0xFFFFFFFE`/`0xFFFFFFFF`, ±∞ semantics). The dense array is now a transient build scratch only: `Bake`/`Edit` = de-brickify (±∞ fill) → evaluate → brickify → discard. `HasSurface` ⇔ any surface cell ⇔ `PresentCount > 0` (the old threadMinMax TLS reduction is gone). Presence rule: brick is stored iff it contains a surface cell or lies within `HaloCells = 4` cells of one (halo derivation: edit results depend on exact old values only where |f| < max(R, r), which 1-Lipschitz bounds to within max(R,r) voxels of the surface; 3.75 → 4. Larger shapes need a larger halo). MC kernel and NavSurfaceJob read bricks directly and skip absent bricks. `sdfResolution` must satisfy `cells % 8 == 0` (33 ✓; BrickGrid ctor throws otherwise).
- **Brick values are stored as half (16-bit, 2026-09-11)**: quantization error ≤ 8e-3 world units in the stored band (≤ 1e-3 in the surface band) — invisible vs the 1.0 voxel size; surface chunk SDF drops to ~47 KB. All float→half conversion happens ONLY in Burst's `BrickCopyJob` (deterministic round-to-nearest-even) → both sides of a border store identical halves, seam invariant verified by smoke (1089/1089 bit-identical). The dense scratch and edit job stay float32 (±∞ deep fills unchanged); `MarchingCubes.Dispatch` takes `NativeArray<half>`, converts to a float32 upload scratch via a Burst job (`HalfToFloatJob`), and the GPU buffer + kernel are unchanged. `Brickify` calls `BrickData.TrimExcess()` after each resize (NativeList keeps its high-water capacity otherwise; the `Capacity` setter would round up to a power of two, +40% on a 32-brick chunk).

## Architecture

Data flow: `ChunkManager.InitializeSdfField` (CPU: `SdfField.Bake` runs `SdfFieldEditJob` over a **transient dense scratch** (33³ floats, -∞ init + all `SdfWorld` shapes) → `Brickify` compresses it into the sparse brick map → scratch disposed; no GPU upload, the brick map stays CPU-side) → `MarchingCubes` (dispatch `MarchingCubes.compute`, uploading the compact brick pool + brick indirection) → `BuildMesh` readback + `RecalculateNormals` → `Chunk.SetMesh`. Runtime edits: `FlyCamera` left-click (raycast, backfaces on, terrain layer) → `ChunkManager.CarveAt` → `SdfField.Edit` per affected chunk (chunk range = `hit ± 3×radius`; it must cover the Sub modification region `{f < r - d}`, not just the carve sphere — see the carve-time bullet below) = de-brickify (absent bricks → ±∞ by sign default) → single-shape `SdfFieldEditJob` over the dense scratch → re-brickify → `MarkChunkDirty(coord)` + `SdfChanged` event → dirty chunks remesh at the end of `UpdateChunks`. Note: the per-chunk edit op history `_chunkEdits` described in older notes is **NOT implemented** — evicting an `SdfField` currently loses its edits on re-init (base bake only). `SdfGenerator` (heightfield noise terrain) was deleted with the Burst refactor (2026-09-01) — the SdfWorld shape list is the only generation source.

### Seamless invariant and resolution rules

Seamlessness depends on **integer-exact lattice decomposition**, shared by `SdfGenerator` (generation) and any future edit code:

```
world = (float3)(chunkCoord * cells + lattice) * voxelSize - halfSize
cells = sdfResolution - 1;  voxelSize = chunkSize / cells;  halfSize = chunkSize / 2
```

- `sdfResolution` (serialized on ChunkManager) = SDF lattice resolution per axis, **both borders included** = `cells + 1`. The MC sampling resolution is derived: `cells = sdfResolution - 1`. A past bug: writing `_voxelSize = size / _resolution` (int/int truncation) silently broke everything — the float cast is load-bearing.
- The kernel reads lattice values from two per-dispatch buffers: `StructuredBuffer<uint> BRICK_INDIRECTION` (64 slots; `0xFFFFFFFE` = absent-solid, `0xFFFFFFFF` = absent-air) and `StructuredBuffer<float> BRICK_DATA` (compact brick pool, `brickID*729 + lz*81 + ly*9 + lx`). Cells in absent bricks are skipped outright (`if (brickID >= 0xFFFFFFFEu) return;`). SDF convention: negative = solid, positive = air.
- `SdfField` = CPU sparse brick map (the truth) — **no GPU copy at all** beyond the per-dispatch scratch upload. `HasSurface` ⇔ any surface cell (min<0 && max≥0) ⇔ `BrickGrid.PresentCount > 0`, computed by `Brickify`'s flag scan; the old threadMinMax TLS reduction was deleted with the sparse refactor. `GenerateChunk` skips MC dispatch + upload for chunks without a surface. Absent-brick reads return deep sign defaults (±MaxValue in `Sample`/nav `V()` — ±∞ would NaN in trilinear `lerp(∞,∞)`; ±∞ is still used inside the de-brickify dense scratch, where only min/max arithmetic happens).
- **Chunk-border seams (verified 2026-09-07 via temp-copy smoke test, `SeamSmoke.cs` in the smoke dir)**: with the integer-exact decomposition and the kernel's local positions `-(size/2) + corner * size/cells` (mirror of the CPU formula; for the demo config cells=32 the voxel size is exactly 1.0), neighboring chunks produce **bit-identical** border lattice values (1089/1089) and bit-identical border vertices (118/118) — the meshes are provably seamless; renders showed no cracks along the border line. The MC tables were also numerically verified face-consistent AND mirror-consistent (shared border faces triangulate identically on both sides; the classic table emits no in-face triangles even for saddle faces — it connects them through the cell interior, so there is also no duplicated border triangle / z-fighting). This holds for generation AND for edits applied to both sides of a border (the edit job and the MC kernel are bit-deterministic on identical inputs).
- **Carve-time border consistency (2026-09-07 seam bug, fixed)**: the invariant above only holds if every edit is applied to EVERY chunk containing a modified lattice point. `SdfEditOp.Sub` = `max(f, -g)` — its modification region is `{f < r - d}`, NOT the carve sphere: for a sphere shape it is the ellipsoid `{|p-C| + |p-hit| < r + R}` (C/R = shape center/radius), i.e. the edit propagates through the shape body along the hit→center direction, far past the carve AABB. `CarveAt` used to edit only `[hit ± r]`, so the far-side chunk at a border never received the edit → shared border lattice values diverged → the two chunks interpolated different border vertices (the visible seam). Fixed by widening the affected range to `hit ± 3×radius`. Exact coverage bound: `margin ≥ R + r/2` (3r ⇔ R ≤ 2.5r — if larger shapes are added, derive the margin from the shape radius). **The sparse brick map (2026-09-11) structurally resolves the deep-value divergence issue**: deep-solid/deep-air values are NOT stored — absent bricks collapse to canonical per-brick sign defaults (one uint per brick), so no per-point divergence can exist outside the halo. This removes the old precondition for `Add`/回填 (the old caveat: `Add` = `min(f, g)` would re-expose seams at border values diverged below the surface band — no longer applies to the stored representation). The remaining constraint is the halo itself: `Add` results depend on exact old values where |f| < max(R, r), so `HaloCells` must stay ≥ ceil(maxShapeRadius / voxelSize) + 1 (currently 4 for R ≤ 3.75, voxel = 1).

### Marching Cubes details (MarchingCubes.compute + CubicMethod/MarchingCubes.cs)

- Kernel iterates `cells³` voxels (4×4×4 threads, dispatch `ceil(cells/4)` per axis — 8×8×8 exceeded D3D11's per-group register budget, warning X4714). The kernel emits **per-triangle vertices in winding (v0, v2, v1)** with the legacy x-ordering dedup swap and NaN snap guard (`|v| < 0.0002f` → snap to corner). Preserve these — they define mesh consistency (dedup) and face orientation.
- Brick read path (2026-09-11): before the corner loop the kernel resolves the cell's brick from `BRICK_INDIRECTION[(i>>3) + bpa*((j>>3) + bpa*(k>>3))]` and returns early for absent bricks (≥ `0xFFFFFFFE`). Corner local coords are `(i&7)+dx` etc. (cell corners always lie inside the cell's own brick: local 0..8, no cross-brick reads — a corner at lattice 32 is local 8 of brick 3). Halo bricks contain no surface cells, so they hit `edgeTable[state] == 0` and return. GPU scratch buffers grow on demand (`_brickBuffer` up to 64×729 floats, `_indirectionBuffer` 64 uints) — uploads only present bricks per dispatch.
- **MC tables flow: `CubicMethod/McTables.cs` (C# port of the 256+4096 values) → ComputeBuffers → shader `StructuredBuffer<uint> edgeTable` / `StructuredBuffer<int> triTable`.** D3DCompiler cannot map dynamic indexing of global `static const` arrays to cs_5_0 ("cannot map expression to cs_5_0 instruction set"), so the tables must NOT go back into the shader as static consts. `Shaders/Tables.compute` is kept on disk only as the reference copy of the data — it is no longer `#include`d. The small LoopTable0/1/2 arrays stay as `static const` in the shader, but their indexing loops MUST keep `[unroll]` (unrolled indices are compile-time constants).
- The kernel does **not** write the Normals buffer. The live path calls `Mesh.RecalculateNormals()` in `GenerateChunk`; the kernel emits unique per-triangle vertex indices, so this yields flat (per-face) normals. `SdfGenerator.ComputeNormals` (SDF-gradient normals) is dead code.
- **Winding & culling**: the kernel's winding `(v0, v2, v1)` orients every front face toward AIR (negative = solid). A carve (`SdfEditOp.Sub`) surface therefore fronts the bowl's INTERIOR — with a single-sided material the far wall of a carved bowl is back-face culled from outside and the hole reads as a see-through gap. The terrain material must be double-sided: `Chunk.Init` sets `_Cull = 0` on the per-chunk material instance (shadow casting was already `TwoSided`).
- `Counters` holds emitted vertex count / index count; `CubicMethod.MarchingCubes.BuildMesh` reads them back (clamped to `maxVertices = cells³ * 6` — the kernel guards writes but the counters keep counting).
- `MarchingCubes` owns one persistent buffer set, reused across chunks; `Dispatch` resets the counters. Released in `ChunkManager.OnDestroy`.

### Chunk streaming, caching and dirtiness

- 350-instance GameObject pool built at runtime via `AddComponent` (no prefabs). Chunk world center = `chunkCoord * chunkSize`.
- `ChunkCache` = coordinate-level LRU cache: one `ChunkData {coord, mesh, sdfField}` entry per coord in a `LinkedList` (head = most recent) + `Dictionary<Vector3Int, LinkedListNode<ChunkData>>` for O(1) touch. Unload returns the GameObject to the pool and keeps the cache; reload is a cache hit. `Trim(capacity, keepAlive)` evicts from the LRU tail, skipping `_activeChunks` (their GameObjects reference the mesh — evicting would pop rendering/collider); called at the end of `UpdateChunks` and `CarveAt`. Capacity = `ChunkManager.cacheCapacity` (default 2000 ≈ 1.9× the ~1050 loaded chunks at maxDistance 200; 0 = unlimited). Replacing a cache entry destroys the old mesh/field.
- **Evicting an `SdfField` is safe memory-wise**: `Destroy()` releases the brick pool + indirection (surface chunks ≈ 32 bricks ≈ 47 KB in half, deep-solid/air chunks ≈ 256 B vs the old dense float32 144 KB — ≈3× combined win from sparsity + half). BUT the edit op history is **not yet implemented** (`_chunkEdits` was documented in old notes but never landed): a re-initialized field re-bakes only the SdfWorld base shapes, so eviction currently loses carves. Re-baking is deterministic (same bricks), so the seam invariant is unaffected; implementing `_chunkEdits` op replay remains future work (each replay op = one dense-scratch pass — batch them per chunk).
- **Dirty tracking lives on chunk COORDS, not on the pooled `Chunk`** (GameObjects are reused across coords — `Chunk.isDirty` was removed as a bug): `ChunkManager._dirtyChunks` (`HashSet<Vector3Int>`) + `MarkChunkDirty(coord)`. On load: dirty or cache-miss → full regenerate (SDF + mesh) and cache update; clean → reuse cached mesh. Loaded dirty coords remesh at the end of `UpdateChunks` (no per-frame budget yet — a large edit will hitch); unloaded dirty coords keep the flag and regenerate on next load.
- Burst `ChunkVisibilityJob` (every `updateFrequency` frames): the 3×3×3 around the player's chunk is always loaded; beyond that, distance + frustum-AABB culling.
- Scene has no "Player" tag → `ChunkManager` falls back to `Camera.main` as the stream center; `FlyCamera` (WASD + mouse, Input System) is the test camera and owns all interaction input (left-click carve, right-click agent navigation — see Pipeline status). "Generated" layer at index 6 in TagManager. No asmdefs. `TutorialInfo/*` is URP template boilerplate; ignore.

### Navigation (custom SDF navmesh, `Scripts/Nav/NavManager.cs`)

Self-built navmesh for DRG-style all-terrain walkers (spiders walk walls/ceilings — Unity NavMesh cannot do arbitrary-up agents, so no NavMeshSurface): nodes are SDF iso-surface samples; A* on the node graph; LOS smoothing. **Right-click** raycasts the terrain and sends the `CustomNavAgent` to the hit point (`SetDestination`); left-click carves and the nav rebuilds + auto re-queries (both live in `FlyCamera` since 2026-09-11).

- Nav cells reuse the same integer lattice decomposition as the SDF (cell (i,j,k) = cube between lattice points i..i+1); a chunk's cells are fully determined by its own `SdfField` → seamless across chunks, no border handling. `NavSurfaceJob` reads the sparse brick map directly: cells in absent bricks are skipped (no surface), and surface-cell gradient stencils (±1 cell) are covered by the halo → exact values.
- Surface detection: single-band rule `minCorner < 0 && maxCorner >= 0` (exact-zero lattice planes yield exactly one node band). Node = cell center projected along the SDF gradient (`pos = center - sdf * normalize(grad)`); node normal = SDF gradient (any orientation). Gradient trilinear is clamped at chunk borders (normals slightly approximate on curved surfaces; positions exact).
- Registry: `_chunkNodes` (chunk coord → `int[cellCount]` node-index array) + pooled `_nodes` list + `_freeNodes` stack. **Adjacency is implicit** (26-neighbor cell-key lookups in A*; no edges stored) → chunk rebuilds reconnect automatically.
- Incremental: subscribes to `ChunkManager.SdfChanged` (fired by `InitializeSdfField` and `CarveAt` only — `GenerateChunk` only reads the field) and rebuilds **synchronously** in the handler.
- A*: **1-indexed binary heap with a sentinel at index 0** — `Pop()` must read `_heap[1]`; the original Pop read `_heap[0]` and returned the sentinel (element 0) on every pop, so the first real pathfinding threw `KeyNotFoundException: key '0'` in `g[cur]` (fixed 2026-09-11, heap unit-tested in the smoke). Decrease-key is lazy (duplicate pushes + closed-set skip). Euclidean weights/heuristic. LOS smoothing: `Los()` is an empty stub — NOT implemented.
- **Agent repath waypoint skip (2026-09-11)**: `Repath` no longer blindly starts at path[1] — it advances `_curPathIndex` while the agent has already passed the perpendicular plane of the waypoint (`Dot(Wk+1 - Wk, P - Wk) >= 0`), skipping behind/duplicate waypoints (the snapped start node is L1-closest, often the just-passed node behind the agent; following it caused a visible 折返跑). The final waypoint is never skipped.
- Nav coverage = chunks that have been rebuilt via `SdfChanged` (init + carve), not the whole ChunkCache.
